# Portfolio project rules

Personal portfolio for Nuwarinda Albert. Vite + React, plain JavaScript (no TypeScript), react-icons.

## Commands

- `npm run dev` - dev server
- `npm run lint` - ESLint, must be clean
- `npm run build` - production build, must succeed
- Run lint and build before calling any step done.

## Stack and styling

- Vite + React, plain JavaScript. **No Tailwind**, no CSS-in-JS.
- Plain CSS, one file per component (`Navbar.jsx` imports `Navbar.css`). Prefix class names with the component (`.navbar-link`, `.footer-title`) so files don't collide.
- Global styles live only in `src/styles/theme.css` (variables) and `src/styles/global.css` (reset, base, utilities).
- Mobile breakpoint is `max-width: 767.98px`; desktop starts at `768px`. **Exception: the navbar** is a floating capsule from `1024px` up and a compact card with a dropdown below it (the `--navbar-height` variable follows the same 1024px switch).

## Colors: always use the theme variables

Every color comes from the CSS variables in `src/styles/theme.css`. **Never hard-code a color** (no hex, `rgb()`, `hsl()` or named colors; `transparent` and `currentColor` are fine). Light/dark mode and the live color customizer only work because everything reads these variables.

The default palette is **"Navy & Gold"** (first preset in `themeConfig.js`; `theme.css` must match it). Presets: Navy & Gold, Classic Blue, Emerald, Teal, Royal Purple, Crimson, Amber/Gold, Slate (a new preset is one entry in `PRESETS`; the customizer shows them all).

| Variable | Use for |
|---|---|
| `--bg` | page background |
| `--bg-alt` | alternate section backgrounds, footer |
| `--surface` | cards, glass panels. **Translucent** (glass), so don't use it where content behind must not show through |
| `--surface-solid` | the opaque version of `--surface`: floating panels, buttons, the customizer |
| `--border` | borders and dividers |
| `--text` / `--text-muted` | body text / secondary text |
| `--heading` | headings |
| `--accent` | **fills, glows, icons, borders, bars**: not text (see below) |
| `--accent-text` | accent used **as text** (labels, links, accent words, active nav text) |
| `--accent-contrast` | text/icons on top of an `--accent` background |
| `--hover` / `--hover-text` | hover colour for fills and borders / for text |
| `--accent-soft` | the accent at 15%: active and hover pills (follows the accent) |
| `--accent-deep` | a rich DARK shade of the accent (OKLCH lightness 0.4; white lettering on it is >= 8:1 for any accent): fills that carry white text, i.e. the customizer's header, active pill, button and footer wave |
| `--glow` | a `box-shadow` value: 24px glow in the accent at 45% (follows the accent) |
| `--brand-navy` / `--on-navy` | fixed navy, and what to draw on it (gold in dark mode, white in light) |
| `--cta-bg` / `--cta-text` / `--cta-shadow` | the "Let's Talk" button (gold on navy in dark mode, navy on white in light) |
| `--shadow`, `--radius`, `--transition` | elevation, corner radius, transition timing |

- Translucent colors: `color-mix(in srgb, var(--surface) 85%, transparent)`, never an `rgba()` literal. Derive gold tints from the accent the same way (`color-mix(in srgb, var(--accent) 30%, transparent)`) so the customizer recolours them.
- `--accent`, `--heading` and `--hover` are overridden at runtime by the customizer, so use them for meaning (highlight, heading, hover), not just as "gold".
- **Never use `--accent` / `--hover` as a text colour.** Bright gold is only ~2.2:1 on the light page. `--accent-text` / `--hover-text` are the same colours in dark mode, and in light mode are darkened (OKLCH lightness capped at 0.47 / 0.43, hue and chroma kept) so any accent stays readable (worst case over 437 accents: 4.79:1). Fills, glows, icons and borders keep the bright `--accent`.
- Text on a colored background uses `--accent-contrast`, not a fixed white/black.
- The theme system (`ThemeContext`, `ThemeToggle`, `ThemeCustomizer`, `theme.css`) is finished. Use it, don't change how it works. `useTheme()` exposes `mode`, `resolvedMode`, `toggleMode`, `colors` and more.
- Transitions: the theme colors fade on `:root`. Components that declare their own `transition` replace the global hover fade on `a`/`button`, so list the properties they need (use `var(--transition)`).
- Respect `prefers-reduced-motion`. `global.css` disables all transitions/animations and smooth scroll under it; don't override that with `!important` of your own.

## Third-party components (uiverse.io, originkit.dev)

When I paste in a component from one of these, before using it:

`src/components/ui/` also holds our own small reusable primitives (e.g. `SectionHeading`, `GlassCard`). Converted from pasted code so far: `ui/Loader` and `ui/BackToTopButton` (both arrived as styled-components; the project does not use CSS-in-JS, so their CSS became plain CSS files and `styled-components` was not installed).

1. Convert it to a React component in `src/components/ui/` (JSX attributes: `className`, `htmlFor`, self-closing tags, camelCase SVG attributes).
2. Move its CSS into a matching CSS file next to it (`ui/Thing.jsx` + `ui/Thing.css`), with class names prefixed so they can't collide.
3. Replace **every** hard-coded color (including gradients, shadows and SVG `fill`/`stroke`) with the theme variables above, so dark mode and the color customizer still work.
4. Keep it keyboard accessible: real `<button>`/`<a>`/`<input>`, visible `:focus-visible`, labels / `aria-label`, no mouse-only interactions.
5. Respect `prefers-reduced-motion` (disable or simplify its animations under that media query).
6. Add a comment at the top of the file with the source URL.
7. Install any library it needs (e.g. `framer-motion`) with npm.

## Content lives in `src/data/`

Text, links and lists are data, not JSX: `site.js` (name, title, location, email, tagline, `navLinks`, `socials` with each one's `icon` and brand `color`, `cvFile`, plus the Contact copy: `contactIntro`, `contactHeading`, `contactForm`, `followMe`, `contactColors`), `about.js` (hero + About content), `skills.js` (`skillsHeading`, `skillsIntro`, `proficiency`, `categories`; see the Skills bullet below), `projects.js` (`projectsHeading`, `projectsIntro`, `projectFilters`, `projects`; see the Projects bullet), `techIcons.js` (technology name -> icon + brand colour), `experience.js` (`experienceHeading`, `experienceIntro`, `experience`, `education`, `keySkills`, `stats`, `experienceCta`; see the Experience bullet) and `logos.js` (organisation logo lookup). Components import from there. To change wording or add an item, edit the data file. A data entry may reference a react-icons component (e.g. `icon: LuLayers` in `focusAreas`); keep JSX out of data files.

## Layout and navigation conventions

- Each page section is `<section id="...">` inside `<main id="main">`. Nav ids come from `navLinks` in `src/data/site.js` (home, about, skills, projects, experience, contact; each has an `icon`, a react-icons component). Education has no link of its own: it will be shown inside the Experience section. Adding a nav entry means adding a matching section id (and listing it in `BUILT` in `App.jsx` once it is a real component).
- `global.css` gives every `section[id]` a `scroll-margin-top` equal to `--navbar-height`, so headings never hide under the fixed navbar. Don't re-declare it.
- Smooth scrolling is `html { scroll-behavior: smooth }`. Scroll with `window.scrollTo({ top })` (no `behavior`) so reduced-motion is respected. For "back to top" use `src/utils/scrollToTop.js`.
- **Routing** (react-router-dom, `BrowserRouter` in `main.jsx`, routes in `App.jsx`): `/` is the one-page home (`pages/Home.jsx`: every section), `/projects/:id` a project's own page (`pages/ProjectDetails.jsx`, a lazy chunk), anything else (and an unknown project id) `pages/NotFound.jsx`. The navbar, footer, back-to-top button and customizer wrap all of them.
  - **Links to a home section** go through `<SectionLink id="about">` (`components/SectionLink.jsx`; `CtaButton` and the footer use it): on the home page it is a plain `<a href="#about">` (so the URL hash updates and sections are directly linkable), from any other page a router link to `/#about`. Never write a bare `href="#"`.
  - **`ScrollManager`** (renders nothing; it also sets `history.scrollRestoration = 'manual'`): opening any page other than `/` scrolls to the top; landing on `/` with a hash scrolls smoothly to that section after the preloader; going back to `/` from a project page (the browser's Back button, "Back to Projects", any section link) jumps to the Projects section (instant); `/projects/x#gallery` scrolls to that section; a link made with `state={{ focusContact: true }}` (the "Let's Talk" buttons) also focuses the contact form's Name field on arrival. Under reduced motion every scroll is instant.
  - **Tab title and description** of a page are set with `useDocumentMeta({ title, description })` and restored when it goes away (`index.html` holds the defaults). A project page uses `"<title> | Nuwarinda Albert"` and the project's description.
  - **Hosting (Vercel):** the site is a static Vite build deployed by Vercel from the `main` branch (see `DEPLOYMENT.md`). `vercel.json` holds everything the host needs: the build settings (`framework: vite`, `npm ci`, `npm run build`, `dist`), the SPA rewrite that serves `index.html` for direct links like `/projects/redhope` (static files and `/assets/*` are not rewritten), permanent redirects from the old HTML site's URLs (`/pages/*.html`, `/old.html`, `/my-resume/my-CV.pdf`), long-lived caching for the hashed `/assets/*` files and two small security headers. `package.json` pins `engines.node` to `22.x` (Vite 8 needs Node 20.19+ / 22.12+). `VITE_WEB3FORMS_KEY` must be set in the Vercel project's Environment Variables (the local `.env` is not deployed). `npm run preview` does the SPA fallback by itself.
- Shared button styles: `.btn` (filled, uses `--accent`) and `.btn-outline` in `global.css`. The pill-shaped "Let's Talk" button is `<CtaButton />` (`ui/CtaButton`); its label and target are `site.cta`.
- Social icons: `<SocialLinks />` (icons mapped from the `id` in `socials`), drawn as round glass buttons that fill with the accent on hover.
- Alternate section backgrounds between `var(--bg)` and `var(--bg-alt)` by position in `<main>`: Hero (`#home`, page background) -> About (`--bg-alt`) -> Skills (`--bg`) -> Projects (`--bg-alt`) and so on.
- The Hero is `<section id="home">` and **is** the "Home" nav link (the logo also scrolls to the top). Its top padding equals `--navbar-height`, so it starts behind the floating navbar.
- **Navbar** (`Navbar.jsx`): a floating capsule (16px from the top, max 1500px) with logo | links | theme toggle | Let's Talk. **At the very top of the page it is fully transparent** (no fill, border, shadow, blur or glow line, so the hero art shows through); once the page scrolls, or the mobile menu is open, it fades into the glass pill (`.is-scrolled` / `.is-open`). One absolutely positioned `.navbar-indicator` slides under the active link; it is moved by writing `--ind-*` CSS variables from `useSlidingIndicator` (no React state), and the first placement is not animated. Below 1024px it is a compact card with a dropdown menu (same links, a sun/switch/moon toggle and the CTA). Scrollspy keeps the last active section when none crosses the band. On a project's own page "Projects" is the current link (`aria-current="page"`); on the 404 page none is. Its links are `SectionLink`s, so they go to `/#about` etc. from other pages, and the logo goes home.
- **Footer** (`Footer.jsx`): four columns on desktop, all colours from theme variables so it re-tints with the preset. (1) the brand column: logo beside the name (heading font) and `site.title` in accent small caps, then `site.statement` (the short professional statement, TODO: edit to taste) and the social buttons; (2) Quick Links; (3) Get In Touch: email, WhatsApp number (`site.whatsapp`, a `wa.me` link) and location; (4) "Let's build something" as a glass card with an accent glow and a `CtaButton`. A glowing top line and diagonal accent streaks made of CSS gradients. Tablet: brand and CTA take a full row each; phone: stacked. The bottom bar is padded clear of the floating customizer / back-to-top buttons.
- **SEO and link previews:** the site address lives in ONE file, `src/data/siteUrl.js` (`SITE_URL`, now `https://nuwarindaalbertgrandeportfolio.vercel.app`; change it when a custom domain is added). `vite.config.js` fills `%SITE_URL%` in `index.html`, which holds the canonical link, `robots`, Open Graph + X (Twitter) card tags and JSON-LD (`WebSite` + `Person`; its `sameAs` list is hand-kept in step with `site.socials`). The share image is `public/og-image.jpg` (1200x630, ~110 KB, navy and gold, name + title + portrait; keep it under 300 KB or WhatsApp may skip it; to change it replace the file). `scripts/generate-seo.mjs` runs before every build (`prebuild` in `package.json`) and writes `public/sitemap.xml` (home + every project in `projects.js`, so a new project is listed automatically) and `public/robots.txt`; both are committed. `hooks/useDocumentMeta.js` sets, per page and restoring afterwards, the title, description, og/twitter title + description, canonical and `og:url`; the 404 page also adds `noindex`. `scripts/generate-seo.mjs` also writes `scripts/static-content.html` (committed): a plain-HTML copy of the portfolio's text built from `about.js`, `skills.js`, `experience.js`, `projects.js` and `site.js` (it loads them through Vite, because they use extension-less imports and react-icons); `vite.config.js` puts it inside `<noscript>` at the `<!--STATIC_CONTENT-->` marker in `index.html`, so tools that do not run JavaScript read the real content and the 15 project links; with JavaScript on it is never shown. Known limit: link-preview crawlers (WhatsApp, Facebook, LinkedIn) do not run JavaScript, so a shared `/projects/<id>` link shows the home page's card; Google does run it, so its results use the per-page tags. Per-project share cards would need pre-rendering.
- **Favicon** (`index.html`, files in `public/`): `favicon-48x48.png`, `favicon-192x192.png` and `apple-touch-icon.png` (180px, on white because iOS fills transparency with black), all cut from the circular portrait `src/assets/profile/circular-favicon.png`. To change it, regenerate the three files from a new square PNG; the old Vite `favicon.svg` is gone.
- **Theme customizer** (`ThemeCustomizer.jsx/.css`, behaviour unchanged, look redesigned): a round palette button (deep accent fill with an accent ring) opens a card above it (a bottom sheet under 480px). Header in `--accent-deep` with a glowing wave edge (an SVG used as a CSS mask, so only its shape matters) and the title in white (`Canvas` in a light colour scheme; the global heading colour is overridden with `color: inherit`), then Mode (three pills, the active one filled), Presets (4x2 glossy round swatches: accent ring, darker centre, tick + dark badge on the chosen one, and a pill with its name or "Custom"), Colors (big picker swatch, name + HEX, a live sample: `Highlighted` / `Heading` / `Hover`), Reset to Default, and a "Beautiful. Modern. Yours." footer strip. The header and footer stay put while the body scrolls. It is anchored, not a modal, so the page stays visible while colours change.
- **Logo** (`Logo.jsx`): picks `src/assets/brand/logo-dark.*` or `logo-light.*` by `resolvedMode`; a single `NAG-Logo.*` is used for both modes; with no file at all it draws a text "NAG" (`site.logoText`) in bold italic with a gold swoosh. Size it with `--logo-height` on the parent.
- **Theme toggle** (`ThemeToggle.jsx`): `variant="pill"` (sun + moon, glowing circle on the active one) or `variant="switch"` (sun, switch, moon). Same button, same accessible name.

## Section building blocks

- **Section heading:** every section starts with `<SectionHeading id="x-heading" label="About Me" icon={FaUser} title="Who I Am" accent="I Am" />` (`ui/SectionHeading.jsx`): a gold-outlined pill label with an icon and a thin gold line beside it on the same row (`align="center"` puts a line on both sides), then a very large heavy-serif title (Playfair 800). `accent` is the part of `title` that gets `.accent`. An optional smaller serif `subtitle` (with its own `subtitleAccent`) goes under the title, as in Skills ("My Skills" / "Technologies I Work With"). Keep the heading content in `src/data/` (`aboutHeading`), and label the `<section>` with `aria-labelledby="x-heading"`.
- **Glass cards and buttons:** `<GlassCard as="article" hover>` (`ui/GlassCard`): `--surface` + blur + 1px `--border` + large radius; `hover` lifts 4px, turns the border accent and adds `--glow`. Never put `useReveal`'s class on a `hover` card (both use `transform`): reveal a wrapper. `<GlassButton href icon>` (`ui/GlassButton`) is the transparent pill with a 2px gold border (fills with `--accent-soft` on hover); `<CtaButton href label icon />` is the `--cta-bg` pill, and `tone="gold"` makes it solid gold with navy text in both modes, `endIcon={FaChevronRight}` adds a chevron that slides right on hover, `iconAfter` moves the main icon after the label. `<SocialLinks size="lg" order={[...]} />` is the 52px outlined variant used in the Hero.
- **Decoration (CSS/SVG only, `aria-hidden`, low opacity, behind the content):** `<DotGrid className="..." />` (radial-gradient dot grid, faded at the edges) and `<Swoosh side="left|right" />` (SVG path with a gold gradient, hugging a bottom corner). Position them from the section's own CSS.
- **Hero** (`Hero.jsx`): text left (about 58%), the cutout photo bottom-aligned on the right (~72% of the screen height) with a slowly rotating two-thirds gold ring and a navy glow behind it, three glass stat cards centred under the text that overlap the bottom of the photo, and the scroll cue (mouse, "Scroll Down", double chevron, gold lines fading outwards; the lines are hidden on phones). Below 1024px the photo goes above the text and everything is centred.
- **About** (`About.jsx`): three zones on desktop (text, photo on a tilted gold slab, Quick Facts card) with the Focus Areas full width below; under 1200px the photo goes above and Quick Facts sits beside the text; under 768px it stacks as label, heading, photo, paragraphs, Quick Facts. The four focus cards get `--card-color` / `--card-on` from `focusAreas` in `about.js` (Full-Stack uses the theme accent, so it follows the customizer; the other three are fixed blue, green and red on purpose). In light mode `--card-ink` darkens the colour for icons so they stay readable.
- **Skills** (`Skills.jsx`, data in `skills.js`): desktop is two columns (text ~45%, picture ~55%) over a row of four category cards. Left: `SectionHeading` with subtitle, the intro with a 4px gold bar, and four proficiency bars. Each bar (`ProficiencyBar`) is a `role="progressbar"` track (`aria-valuenow/min/max`, `aria-label`) whose gold fill grows 0 -> value and whose percentage counts up the first time it is half visible, once only; the counting number is `aria-hidden`, and under reduced motion the final values show at once. Right: the laptop picture, slightly wider than its column and starting at the column's left edge so any overflow goes right and never over the text; a pulsing `--accent` glow behind it, a 6s float, and a `useTilt` parallax (max 6deg). Under 1024px the picture goes above the text (max 520px, 360px on phones), cards go 2x2, then one column under 640px; bar rows then stack label above bar. If the picture file is missing the picture and glow are not rendered and `.skills-top--solo` lets the text take the full width.
  - **`categories` format:** `{ id, title, color, icon, items: [{ name, icon, color?, adaptive? }] }`. The card subtitle is generated from the first four item names, so don't write one. `color` is the card colour (`'var(--accent)'` for the gold card so it follows the customizer; green, purple and red are fixed hex on purpose) and becomes `--card-color`. An item's `color` is its brand colour (`--icon-color`); an item without one (the "Other Skills" icons) uses the card colour; `adaptive: true` is for logos that are black in real life (Flask) and makes them use `--text`.
  - **Icon legibility:** brand and card colours are corrected in CSS, not by hand per theme: dark mode lifts the lightness of dark brand colours (`--icon-ink`: `max(l, .68)`), light mode caps it (`--icon-ink`: `min(l, .58)`; `--card-ink`, used for the card's icon and border tints: `min(l, .47)`), using `oklch(from var(--x) ...)` inside `@supports`, and a `color-mix` fallback. Keep new icons going through `--icon-color` so they get the same treatment (the test: every icon at least 3:1 against its card in both modes).
  - **Tooltips:** each item icon is a focusable `span` (`tabIndex=0`, `role="img"`, `aria-label` = name) with `data-tip`; the tooltip is its `::after` (`content: attr(data-tip)`), shown on `:hover` and `:focus-visible`. No JS. Don't give the icon `overflow: hidden`.
- **Projects** (`Projects.jsx`, data in `projects.js`, pictures in `src/assets/projects/<id>/`):
  - **Layout:** top row = heading + intro (left) and the filter tabs over the featured card (right); the project grid (4 columns) and an "Explore All Projects" pill below. Under 1200px the heading sits above the filters/featured card and the grid has 3 columns; under 1024px the featured card stacks (cover on top, 16:10) and the grid has 2; under 640px one column. The grid shows 4 cards before Explore All (3 where it has 3 columns, so a row is never left with one orphan: `useGridColumns`). The filter row scrolls sideways on phones with no scrollbar.
  - **Data:** a project is `{ id, title, titleAccent?, subtitle, description, details, highlights[], tech[], categories[], featured, accentColor, liveUrl, codeUrl, codePrivate, status? }` (comments at the top of `projects.js` explain each field). `categories` are `fullstack | ai | web | mobile`; the first is the "main" one (its icon is on the generated cover, its label is the fallback subtitle). The first `featured` project that matches the filter is the big card, the rest go in the grid. `// TODO` comments mark what still needs filling in (links, tech lists, longer descriptions). Optional: `initials`, `imageFolder`, `motif: 'heartbeat'`.
  - **Link rules** (`ProjectLinks.jsx`, same in the card, the featured card and the project page's hero): no `liveUrl` = no Live Demo; `codePrivate` = a muted non-clickable "Private Code" pill (a `<span>`); no `codeUrl` and not private = no View Code; external links open in a new tab with `rel="noopener noreferrer"`. A grid card with no buttons shows a plain "View Details" hint; the featured card always has a "View Details" link to the project's page.
  - **Whole-card click:** the title is a real `<Link class="project-card-open" to="/projects/<id>">` whose `::after` stretches over the card (the link buttons sit above it with `z-index: 2`), so a click anywhere on the card (outside its buttons) opens the project's page. Keep `.featured-body` / `.project-card-body` un-positioned, or the stretched layer shrinks to that box. (There is no modal any more.)
  - **Pictures** (`data/projectImages.js`, found with `import.meta.glob`): `cover.png|webp|jpg` is the card image; every other image under the folder (sub-folders too) is a gallery screenshot on the project page, in natural filename order (2 before 10); an optional `architecture.png|webp|svg` at the root of the folder is the diagram of the Architecture section and is left out of the gallery; gallery captions come from the file name or from the project's `captions` (keyed by file name). A folder matches a project when its name equals the id after tidying (lower-case, `(brackets)` dropped, punctuation -> `-`), so `Medcare` and `glamazon(salon-app)` work as they are; `imageFolder` points at any other name. No cover (or a file that fails to load) = a generated cover (`ProjectCover.jsx`: accent gradient, big faint category icon, initials). Everything under `src/assets/projects` is bundled, so keep screenshots small (WebP). Video files (`*.mp4`) are ignored. **Screenshots in use:** `CornerShop` (-> E-commerce Prototype via `imageFolder`, desktop shots 1500 px wide), `jobquest-app` (-> `jobquest`, `imageFolder`), `veloce(bike-app)` (-> `veloce`) and `glamazon(salon-app)` (-> `glamazon`), phone shots 571-720 px wide. Files are WebP named `NN-what-it-is.webp` (the number sets the order, the rest becomes the caption: `04-role-selection-page.webp` -> "Role selection page"), sub-folders flattened. Each folder has a `cover.webp` (1600x1000): a cropped screenshot for the desktop app, a three-phone composite on a brand-colour gradient for the mobile apps; the cover is slide 1 of the gallery (captioned with the project title), so the screen it shows is not repeated in the gallery. The original PNG/JPG files were moved to `src/assets/originals/projects/<folder>/` (not bundled). `Medcare/` is empty. To add pictures for another project: drop WebP screenshots in its folder; no code changes. The gallery viewer is 16:10; when the shown picture is portrait (a phone screenshot) it switches to 3:4 under 640 px (`.pg-open--portrait`), and thumbnails are anchored to the top (`object-position: top`) so they show the screen's header.
  - **Animation** (framer-motion, loaded lazily: `<LazyMotion features={() => import('../utils/motionFeatures')}>`, so `domMax` is its own chunk): filter changes fade/scale cards out and in and slide the rest (`layout`); Explore All animates the new cards; the heartbeat line is a CSS dash-offset transition that runs once when the cover is first seen. Under reduced motion cards only fade (nothing waits hidden for a scroll) and `layout` is switched off explicitly: framer's own `reducedMotion="user"` only covers transforms, not layout animations. A card only fades in once it is on screen, so after a filter click the cards below the fold appear as you scroll to them.
  - **Icons and colours:** tech chips (`ui/TechChips.jsx`) use `techIcons.js`; an unlisted name still works (generic icon). Brand and project colours go through the same OKLCH lightness clamps as Skills (`--chip-ink`, `ProjectTitle.css`) so they read in both modes. `accentColor` is data; the CSS only mixes it with theme variables.
- **Experience** (`Experience.jsx`, data in `experience.js`; it also holds Education): desktop is two columns (heading, intro and the floating scene on the left ~45%; the Experience/Education switch and the timeline on the right ~55%), then a full-width bottom row (stats + "Let's Work Together"). Under 1024px the heading and a smaller (max 420px) centred scene go on top and the timeline is full width below; under 640px the logo panel moves to the top of each card (72px) with the date pill beside it, key skills go to one column and the stats stack above the button. The left column is as tall as the timeline and the scene is `position: sticky` inside it, so the section uses `overflow-x: clip` (not `hidden`, which would stop sticky working).
  - **Data:** an experience entry is `{ id, role, organisation, type, start, end, summary, achievements[], logo, logoBg, icon }`; an education entry is `{ id, award, institution, start, end, note, current? }` (`current: true` shows the "Current" badge). Newest first. The date pill prints `start –` over `end`. Stats are `{ icon: 'code'|'users'|'headset', value, label }`: **a stat with an empty `value` is hidden and the whole row is hidden while all are empty** (no made-up numbers; fill the values in `experience.js`, e.g. `'12+'`); values count up when seen.

## Verifying UI work

Don't trust the build alone. Run the app in a real browser (Chrome via playwright-core works here), check behavior at phone (320-375px), tablet (768-1024px) and desktop widths, in light and dark, with a custom accent from the ThemeCustomizer, and with `prefers-reduced-motion`. Look at screenshots too: a DOM check will not catch a layout that reads wrong. For text over glass, gradients or the hero art, measure contrast on the rendered pixels (hide the glyphs, screenshot the text's line boxes, compare with the worst pixel): computed colors alone can't see what is behind the text. Headless Chrome renders in software, so judge animations by their timing and state (e.g. `document.getAnimations()`), not by frame rate, and sample them from outside the page every ~60-100ms (a per-frame `requestAnimationFrame` loop inside the page can starve the renderer and stall the animation being measured). To see where a `window.location.href = 'mailto:...'` goes (headless Chrome opens nothing), listen to the CDP event `Page.frameRequestedNavigation`; to test a form without sending real mail, build with a fake key (`VITE_WEB3FORMS_KEY=x vite build --outDir ...`) and fulfil the request with `page.route`. Playwright's `click()` scrolls the page when it thinks a button is obscured (e.g. under the fixed navbar); for tests where scroll position matters (anything that reveals on scroll), click from inside the page (`el.click()`). `loading="lazy"` images only load once on screen, so a test that reads `naturalWidth` must scroll them into view and wait first.
